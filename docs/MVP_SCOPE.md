# AI 园林助手 MVP 范围与迭代规划

## 1. 文档目的

本文明确第一版的功能边界、当前完成状态、验收条件和后续优先级。当前进度基线更新于 2026-08-07。项目按功能结果推进，不规定 48 小时、七天或逐日开发任务。

状态说明：

| 状态 | 含义 |
| --- | --- |
| 已完成 | 已在当前代码中实现，并通过与该能力相称的检查或测试 |
| 部分完成 | 主流程可用，但仍缺少明确的子能力或真机验证 |
| 未开始 | 当前代码尚不具备，需要后续实现或外部配置 |
| 暂缓 | 已确认本轮不推进，不作为当前版本验收阻塞项 |

## 2. MVP 成功定义

本地 MVP 的核心闭环是：

> 识别或手动录入植物 -> 加入个人花园 -> 记录养护 -> 创建任务 -> 在应用内完成任务

同时，用户可以通过图片、文字或两者组合获得有边界、可执行的初步诊断建议。当前版本还需要在此基础上完成体验版真机验收；微信订阅消息暂缓，不计入本轮成功条件。

### 3.3 P2：后续候选

- 用户登录、云同步和多设备使用。
- 个性化养护计划和生长相册。
- 天气联动提醒。
- 用户纠错和识别质量反馈。
- 扩充由项目内数据文件维护的植物知识内容。

## 4. 明确不进入 MVP

- 付费、会员、广告、订单和积分体系。
- 植物商城或交易。
- 用户社区、评论、关注和私信。
- 专家在线问诊。
- 面向园林工程或农业生产的批量管理。
- 原生 App 和其他小程序平台同时发布。
- 未经审核的高风险农药配比或用量方案。

## 5. 后续工作池

以下工作按依赖和产品价值安排，不绑定具体日期：

### 微信发布能力

- AppID、基本信息、类目和微信认证已完成；等待备案管局审核结果。
- 微信开发者工具调试已通过；上传体验版，在真实设备验证拍照、相册、路由、本地存储和核心业务闭环。

### 已暂缓事项

- 本地真实密钥联调通过后，仍需完成 HTTPS 部署、微信身份鉴权、调用预算保护和运维监控。

## 6. 发布验收

### 功能

- 识别、诊断、花园、养护记录和任务主流程均可在真机完成。
- 本地数据在小程序重启后保持一致。
- 图片、文字以及图文组合诊断均有明确反馈。
- 同一待办重复点击不会生成重复完成记录。
- 用户可以删除植物、养护记录、历史和全部本地数据。
- 首页搜索结果和常见植物卡片都能进入对应植物知识详情。

### 微信平台

- 相机和相册授权符合当前微信规范。
- 授权拒绝不阻断其他本地功能。
- 体验版在管理员、开发者或体验成员的真实设备上完成核心流程验证。

### 数据与安全

- 前端不保存第三方 AI 密钥。
- 图片上传前已说明用途和处理方式。
- 诊断结果明确为参考建议，并包含必要的人宠安全提示。
- 云端数据启用前已提供隐私规则、删除机制和第三方处理说明。

### 工程质量

- TypeScript、ESLint、Jest、H5 构建和微信小程序构建全部通过。
- 关键页面无阻断操作的控制台错误。
- 所有未完成 P0 项都应记录依赖和验收方式，但不强制按天排期。

## 7. AI 服务选型标准

| 维度 | 关注点 |
| --- | --- |
| 能力 | 常见植物覆盖、病虫害识别、图文联合理解 |
| 准确性 | 候选结果质量、低可信度表达、中文建议质量 |
| 响应时间 | 普通图片的端到端等待时间 |
| 稳定性 | 超时率、错误率、并发限制和服务可用性 |
| 成本 | 单次调用成本、免费额度和项目预算上限 |
| 隐私 | 图片保存、训练用途、数据地域和删除机制 |
| 接入方式 | API 文档、鉴权、返回结构和供应商锁定风险 |

模型或厂商确定前，产品只描述“模拟识别”或“模拟诊断”，不宣传具体模型能力和准确率。

## 8. 范围控制

- 首先保证识别、诊断、管理和提醒闭环稳定，再增加展示型功能。
- 新需求若不能直接改善核心闭环，默认进入 P2 评估。
- 涉及敏感权限、付费或用户公开内容的需求必须单独评审。
- 真实 API 接入不应迫使页面重写；若接口结构不适用，应先修正服务抽象。
- 进度以功能状态和验收结果衡量，不使用原有极限 Sprint 或七天任务表。
