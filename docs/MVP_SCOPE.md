# AI 园林助手 MVP 范围与迭代规划

## 1. 文档目的

本文明确第一版的功能边界、当前完成状态、验收条件和后续优先级。项目按功能结果推进，不规定 48 小时、七天或逐日开发任务。

状态说明：

| 状态 | 含义 |
| --- | --- |
| 已完成 | 已在当前代码中实现，并通过基础编译检查 |
| 部分完成 | 主流程可用，但仍缺少明确的子能力或真机验证 |
| 未开始 | 当前代码尚不具备，需要后续实现或外部配置 |

## 2. MVP 成功定义

本地 MVP 的核心闭环是：

> 识别或手动录入植物 -> 加入个人花园 -> 记录养护 -> 创建任务 -> 在应用内完成任务

同时，用户可以通过图片、文字或两者组合获得有边界、可执行的初步诊断建议。正式微信版本还需要在此基础上完成订阅消息和真机验收。

### 3.3 P2：后续候选

- 真实植物识别服务和大模型辅助诊断。
- 用户登录、云同步和多设备使用。
- 个性化养护计划和生长相册。
- 天气联动提醒。
- 用户纠错和识别质量反馈。
- 当内容规模确有需要时再评估独立内容运营后台。

## 4. 明确不进入 MVP

- 付费、会员、广告、订单和积分体系。
- 植物商城或交易。
- 用户社区、评论、关注和私信。
- 专家在线问诊。
- 面向园林工程或农业生产的批量管理。
- 原生 App 和其他小程序平台同时发布。
- 未经审核的高风险农药配比或用量方案。

## 5. 后续工作池

以下工作按依赖和产品价值安排，不绑定具体日期：

### 微信发布能力

- 注册并配置正式微信小程序 AppID。
- 在微信开发者工具中验证拍照、相册、路由和本地存储。
- 确定后端方案并设计任务、用户授权和消息发送数据。
- 申请订阅消息模板，实现定时调度、发送失败处理和点击跳转。

### 真实 AI 接入

- 使用固定测试集比较候选服务的准确性、响应时间、成本和隐私规则。
- 将密钥和第三方调用放在服务端，不把密钥写入小程序。
- 保持现有业务数据结构，增加超时、限流、重试和 Mock 降级。
- 针对低可信度结果提供候选项和补拍引导。

### 质量完善

- 完成真实设备上的完整主流程和权限拒绝测试。
- 增加 Store、任务重复规则和级联删除单元测试。
- 增加图片压缩、存储失败、重复点击和数据升级处理。
- 优化演示图片体积并复核素材许可。

## 6. 发布验收

### 功能

- 识别、诊断、花园、养护记录和任务主流程均可在真机完成。
- 本地数据在小程序重启后保持一致。
- 图片、文字以及图文组合诊断均有明确反馈。
- 同一待办重复点击不会生成重复完成记录。
- 用户可以删除植物、养护记录、历史和全部本地数据。

### 微信平台

- 相机、相册和订阅消息授权符合当前微信规范。
- 授权拒绝不阻断其他本地功能。
- 订阅消息模板、发送时机和目标页面通过真机验证。

### 数据与安全

- 前端不保存第三方 AI 密钥。
- 图片上传前已说明用途和处理方式。
- 诊断结果明确为参考建议，并包含必要的人宠安全提示。
- 云端数据启用前已提供隐私规则、删除机制和第三方处理说明。

### 工程质量

- TypeScript、ESLint、Jest、H5 构建和微信小程序构建全部通过。
- 关键页面无阻断操作的控制台错误。
- 所有未完成 P0 项都有明确负责人、依赖和验收方式，但不强制按天排期。

## 7. AI 服务选型标准

| 维度 | 关注点 |
| --- | --- |
| 能力 | 常见植物覆盖、病虫害识别、图文联合理解 |
| 准确性 | 候选结果质量、低可信度表达、中文建议质量 |
| 响应时间 | 普通图片的端到端等待时间 |
| 稳定性 | 超时率、错误率、并发限制和服务可用性 |
| 成本 | 单次调用成本、免费额度和项目预算上限 |
| 隐私 | 图片保存、训练用途、数据地域和删除机制 |
| 接入方式 | API 文档、鉴权、返回结构和供应商锁定风险 |

模型或厂商确定前，产品只描述“模拟识别”或“模拟诊断”，不宣传具体模型能力和准确率。

## 8. 范围控制

- 首先保证识别、诊断、管理和提醒闭环稳定，再增加展示型功能。
- 新需求若不能直接改善核心闭环，默认进入 P2 评估。
- 涉及敏感权限、付费或用户公开内容的需求必须单独评审。
- 真实 API 接入不应迫使页面重写；若接口结构不适用，应先修正服务抽象。
- 进度以功能状态和验收结果衡量，不使用原有极限 Sprint 或七天任务表。
